## 5. Facts that changed the plan (vs. my earlier assumptions)

1. Toolchain is Vite+ (`vp check`), not ESLint/Prettier; gate = `vendor/bin/sail composer ci:check`.
2. No Pest browser plugin / Vitest → no E2E/TS unit tests without approval; use fixtures + narrow feature tests + manual checklist.
3. `frontend/` must be added to Vite+ lint/fmt ignore lists.
4. Fonts: reuse `bunny()` in `vite.config.ts`; no Fontsource dependency.
5. `app.blade.php` is hard-forced dark → light mode requires an approved Blade edit.
6. Passkeys, receipts page, bulk mark-read, lead notes, preparer assignment, server-side search/filters/pagination **already exist**.
7. Convert-lead sends no invite email — don't claim it in the dialog copy.
8. Verify-email isn't live (feature disabled).
9. Legal pages are three separate static pages, not a shared `show`.
10. Several Radix packages (switch, radio-group, tabs, alert-dialog, popover) aren't installed — use native/alternative implementations unless approved.
11. `OverviewTest` pins the backend `next_step_text` string, so the new next-step copy must come from a frontend map.
12. Error handler also serves **403**.
