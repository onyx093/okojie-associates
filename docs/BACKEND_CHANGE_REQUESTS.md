### New backend specs from decisions

**D-07 → BE-16.** Route `referral.redirect` = `GET /r/{code}` (public, throttled). Always redirects (302) to `route('contact', ['ref' => $code])` preserving other query params; never reveals whether a code exists; an invalid code shape redirects to the contact page without `ref`. `AttributeReferral` (30-day cookie) keeps working because the redirect lands on `contact?ref=…`. `ReferralController` builds `referralLink` with the new route (index page and the invite mail). Tests: redirect cases, attribution after redirect, link format; existing `/contact?ref=` flows (`LeadFormsTest`, `RegistrationTest`) stay unchanged.

**D-10 → BE-17.** Migration `users.compact_tables` (bool, default false) and `users.reduce_motion` (bool, default false). `PATCH settings/appearance/preferences` (`appearance.preferences.update`, auth only, boolean validation, own account only). `HandleInertiaRequests` shares `auth.user.preferences { compactTables, reduceMotion }`. The UI seeds its display-preferences context from the server and saves changes with an Inertia (optimistic) PATCH.
